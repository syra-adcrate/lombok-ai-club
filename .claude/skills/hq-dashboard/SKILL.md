# /hq-dashboard — regenerate the Second Brain graph

The graph is a single self-contained HTML page (canvas force graph, dark theme, Today
+ filter panels, no external resources) generated by `generate.py` in this skill's
folder. It lives at **`dashboard/public/second-brain.html`**, served by the Content
Studio app (Express `server.js` and the Cloudflare worker both serve
`dashboard/public/` statically) in its **Second Brain** tab. All scanning is
repo-relative — the `employees/` tree stays portable.

## Steps

1. If routines may be running, `git pull --rebase` first so the graph reflects the
   latest memory.
2. Regenerate (default output is the committed app page):

   ```
   python3 .claude/skills/hq-dashboard/generate.py --root .
   ```

3. Commit `dashboard/public/second-brain.html` (message
   `hq-dashboard: refresh second brain`) and push per the standard commit-first →
   pull/rebase → push protocol. When run inside an employee routine (e.g. Aria's
   standup), fold this into that routine's single end-of-run commit.
4. Optional, only if the user wants a claude.ai Artifact copy: publish the same file
   with the Artifact tool (favicon `🕸️`), reusing the existing "Lombok HQ" artifact
   URL via `action: "list"` — never mint a second URL.
5. Report node/edge counts.

## Notes

- The Today panel shows open/surfaced insights across all employees (open first) and
  the roster with `last_run` health; the filter panel has per-employee color groups,
  node-type toggles, and hide-done — matching the Obsidian-graph reference.
- The generator parses both item formats in use (template `- [status | date | TAG]`
  and `- date · **status** · text`); statuses `queued`→open, `taught`→done.
- Privacy: the page renders memory content and the repo is public — memory must
  contain no real email/calendar/PII content until the employees/ tree moves to the
  private repo (`employees/PRIVACY.md`).
- Employees with `status: removed` are excluded from the graph.
